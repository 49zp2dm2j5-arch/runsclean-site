01 / Where the course starts

The timeout that already wrote the record.

A tool call times out. The server had already changed the record before the connection dropped. Retry, and you might finish the job or do it twice. The client can't tell which from what it got back.

Most MCP tutorials stop at the first green tool call on one process. This course starts where that demo stops being true: two replicas, a gateway that routes on headers, a human approval in the middle of a call, a token issued for another service. Each of those turns into behavior you write down and prove with a test.

02 / Labs

Fourteen labs. One command each.

Every module has a lab, and every lab runs with one command: bash verify.sh. Docker Compose is the only thing you install. Images are pinned by digest, no lab asks for an account or an API key, and each one ships with checks that break the code on purpose, so you can see the tests notice the defect they were written for.

05 / Fit

Who it's for

  • Backend engineers building MCP servers that expose real tools and data
  • Platform engineers who own the gateway, the auth and the uptime around those servers
  • Engineers chasing a bug that only shows up on the second replica or after a retry
  • Developers with an MCP integration on revision 2025-11-25 who need a tested way to move to 2026-07-28
 

What you need

  • Python you're comfortable with: running tests and reading a traceback. TypeScript helps in module 1, but you can follow the Python side only
  • Reading HTTP requests, JSON and command-line output
  • A computer that can run Docker Compose with a few containers at once
  • Internet access the first time each lab runs, to pull images and pinned dependencies

Checked before it's taught

This course contains the use of artificial intelligence. The technical side is held to a stricter rule: 224 claim records name the spec section they come from and the date they were checked, and a lesson's lab has to pass before its narration is written.

No cloud bill

Everything runs on your machine in Docker. No cloud account, no API key, no model provider. You'll want a computer that can run a few containers at once.

Dated, on purpose

MCP changes. The course says which revision it covers, which claims were checked on which date, and has a whole module on migrating from 2025-11-25.

06 / Questions

Before you enroll

Which version of MCP does the course cover?

Revision 2026-07-28, the one without the initialization handshake or protocol sessions. Module 9 covers migrating a server written for 2025-11-25, including the features that are deprecated but still in the spec.

Do I need to know TypeScript?

No. Python carries the course. Module 1 builds the same request contract in TypeScript too, so you can see which rules come from the protocol and which from a language, but you can follow it reading the Python side only.

Do I need an API key or a cloud account?

No. Every lab runs locally with Docker Compose. The authorization labs bring their own local authorization server, and nothing calls a model provider.

Is this an intro to MCP?

It's intermediate. You should be comfortable reading HTTP requests, JSON and test output. If you've built one MCP tool and wondered what happens behind a load balancer, you're the person it was written for.

How long is it?

57 lessons and about seven hours of video, plus the labs, which take longer than the videos if you do the challenges. Nine core modules, then five bonus modules on agent security, resources and prompts, production gaps, design trade-offs and a reference server.

Who's behind Runs Clean?

Runs Clean is a small publisher of engineering courses. There's no invented instructor with a stock photo. The courses are published under the brand, and what we put forward instead of a résumé is the standard: tested labs, sourced claims, dated material.
